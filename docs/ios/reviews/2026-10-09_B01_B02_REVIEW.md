## Findings requiring B01-R1

### R1 — Markdown export breaks against the actual server (P1)

`src/api/client.ts` unconditionally calls `response.json()` on successful non-204 responses. The shared backend `_routes/comparisons/[id]/actions.ts` sends Markdown using `Content-Type: text/markdown` and `.send(result.markdown)`. The new export test mocks `apiFetch` to return a JSON object containing `markdown`, bypassing the actual transport mismatch.

Required: explicit typed response decoding for JSON/text, correct error-body handling, and fetch-boundary tests using real Response objects. Markdown must survive unchanged, including newlines. Preserve JSON export semantics. Show a redacted staging export when available.

### R2 — Refresh/retry corrupts cached job shape (P1)

`manageComparison` now returns an acknowledgement. Detail screen `manageMutation.onSuccess` still calls `setQueryData(['comparisonDetail', id], updatedJob)`. Backend retry returns `{success:true,message:...}`; refresh returns its own acknowledgement. Neither is a validated ComparisonJob. Replacing the job loses status/result and can stop polling/rendering.

Required: validate acknowledgement; invalidate/refetch the real detail and related usage/history. Do not synthesize a job from acknowledgement. Component/query integration test must verify cached data remains a valid job and running state resumes from server detail.

### R3 — Missing data still produces research assertions (P0)

Detail parsing falls back on any object with `id`, supplies `status:'completed'`, `progress:100`, and `activeStep:8`, and uses `||` which turns valid zeroes into defaults. Creation also accepts arbitrary `id` responses after schema failure. Schemas retain invented fact confidence 0.85, source/follow-up confidence 0.9, reliability `Official`, and freshness `Fresh`. Usage still maps a malformed success `{}` into an apparently known free plan and 5/10/3 quotas. `validateComparison` defaults malformed success to `canStart:true`.

Required: validated, explicit legacy adapters only; reject unsupported/malformed payloads. Represent absent confidence/reliability/freshness/quota as unknown and update rendering accordingly. Keep legitimate structural defaults only where they do not assert research truth. Add tests for missing confidence, `{id:'x'}`, malformed statuses, zero progress, `{}` usage/validation, and unlimited quota representation.

### R4 — Mutation acknowledgement and rollback are insufficiently proved (P1)

`toggleFavorite` accepts missing server favorite fields by echoing requested state. Detail job schema lacks `isFavorited`; the current backend detail serializer must be checked before assuming it provides that field. History/detail mutations do not serialize rapid taps or protect rollback from overlapping requests. Rating displays submitted state before server confirmation. The cited favorite test only checks rejected API Promise propagation; it does not render the screen or exercise cache rollback.

Required: validate acknowledgement and organization envelope, use authoritative persisted favorite state (verify whether a shared detail change is needed), serialize/disable per-record pending operations or implement race-safe mutation ownership, and distinguish rating pending/confirmed/error. Test UI/cache behavior for failed, overlapping, malformed-success, and refetch cases. Source-feedback success must validate the backend's `{feedback:row}` envelope rather than accept arbitrary 2xx JSON.

### R5 — Cancellation and authorization contract still has holes (P1)

An already-aborted external signal is not propagated before fetch, the abort listener is never removed, and the timer stops when headers arrive rather than when body decoding completes. Token getter exceptions remain swallowed. Headers supplied by callers can include Authorization even for untrusted origins; existing tests cover only the automatic token. Retry-After only handles integer seconds, not HTTP-date form, and 500 retry metadata disagrees with the claimed server-outage policy.

Required: check pre-aborted signals, clean up listeners, cover full decode within timeout/cancellation, define auth-token failure policy, normalize Headers inputs and enforce the stated external credential policy, and document/test retry rules including HTTP-date/invalid headers. Do not add automatic expensive mutation retries.

### R6 — Example and partial-source states remain ambiguous (P1)

Prefix-selected examples still use the production detail route/UI without a persistent example banner; the screen derives `SOURCE VERIFIED` merely from nonempty context. Example mutation controls can call live endpoints using demo IDs. Source aggregation swallows every detail failure and can present `[]` as genuine empty.

Required: explicit example provenance, visible label, and disabled/isolated live mutations. Verification labels require a defined evidence policy. Return recoverable all-failed/partial aggregation state with honest scope. Tests must distinguish true empty, all-failed, and partial success.
